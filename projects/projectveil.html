CASE 01

장비 복원을 하나의 작업으로 다루기

문제·요구사항
무기·보조 장비·방어구를 순서대로 적용할 때 중간 단계가 실패하면 장비와 GAS 효과가 서로 다른 상태로 남을 수 있습니다.
구현과 판단
아이템 참조와 슬롯 조합을 먼저 검사하고 변경 전 상태를 스냅샷으로 보관합니다. 적용에 실패하면 새 상태를 정리한 뒤 이전 장비와 효과를 복구합니다.
  1. 사전 검사
  2. Snapshot
  3. 단계별 적용
  4. 실패 시 Rollback

구현 범위와 확인 항목

  • 보조 장비·방어구 적용 실패를 강제로 발생시키는 테스트
  • 무기 해제 후 실패하는 경로와 정상 복원 경로를 함께 구성
  • 장비 포인터 외에 Speed·Defense·기본 공격 상태 비교
핵심 코드 펼쳐 보기 ＋
const FRestoreSnapshot Snapshot = CaptureRestoreSnapshot();

if (DidRestoreStepFail(EPV_EquipmentRestoreStep::Armor,
    EquipArmor(ArmorDefinition)))
{
    RollBackToSnapshot(Snapshot);
    return EPV_EquipmentRestoreResult::RuntimeApplyFailed;
}

CASE 02

전투 상태와 연출 이벤트의 전달 구분

문제·요구사항
같은 프레임에 발생한 여러 연출 이벤트를 단일 복제 값에 담으면 앞선 중간값을 보존하기 어렵습니다.
구현과 판단
전투 Cue를 Sequence가 있는 버퍼에 보관하고 마지막으로 소비한 번호 이후의 항목을 순서대로 처리합니다. 최초 수신 시에는 현재 가장 큰 번호를 기준으로 시작해 과거 연출 재생을 피합니다.
  1. 서버 Cue
  2. Sequence + Buffer
  3. 미소비 항목 선택
  4. 순서대로 연출

구현 범위와 확인 항목

  • 미소비 이벤트 선택·정렬·재소비 방지 규칙 테스트
  • 버퍼 크기 16개 제한 및 오래된 항목 정리
  • Sequence 간격 감지와 최초 수신 기준 테스트
핵심 코드 펼쳐 보기 ＋
if (Cue.Sequence > LastConsumed)
{
    Result.Add(Cue);
}
Result.Sort([](const FPV_CombatCue& A, const FPV_CombatCue& B)
{
    return A.Sequence < B.Sequence;
});
버퍼·소비 규칙 ↗규칙 테스트 ↗

규칙 테스트와 실제 네트워크 환경의 검증은 구분합니다. 버퍼 수용량을 넘는 지연·패킷 손실 상황의 연출 복구는 추가 확인 대상입니다.

CASE 03

동일 비용에서도 재현 가능한 헥스 경로

문제·요구사항
같은 비용의 후보가 여러 개일 때 선택 순서가 명확하지 않으면 같은 입력으로도 다른 경로를 고를 수 있습니다.
구현과 판단
A* 후보의 우선순위를 비교하고 동률이면 Q·R 좌표 순으로 판단합니다. 이웃 타일은 고정된 방향 순서로 탐색하며, 이동 범위에서는 통과 가능 여부와 정지 가능 여부를 분리합니다.
  1. 출발·목표
  2. 비용 + 좌표 비교
  3. 고정 순서 탐색
  4. 경로 반환

구현 범위와 확인 항목

  • 같은 입력의 반복 탐색 결과 배열 비교
  • 장애물 우회·진입 비용·탐색 예산 경계 테스트
  • 이동 범위와 경로 재구성 테스트
핵심 코드 펼쳐 보기 ＋
if (A.Priority != B.Priority)
    return A.Priority < B.Priority;
if (A.Coordinate.Q != B.Coordinate.Q)
    return A.Coordinate.Q < B.Coordinate.Q;
return A.Coordinate.R < B.Coordinate.R;
A* 구현 ↗경로·이동 범위 테스트 ↗

CASE 04

콘텐츠 오류를 같은 규칙으로 검사하는 도구

문제·요구사항
Data Asset이 늘어나면서 누락 참조나 공격 타이밍 설정 오류를 수동으로 확인하기 어려워집니다.
구현과 판단
Asset Registry를 조회하는 에디터 Commandlet에서 캐릭터·공격·조우 정의와 명명 규칙을 검사하고, 발견 위치와 내용을 CSV·JSON으로 출력합니다. 오류가 있으면 종료 코드 1을 반환합니다.

구현 범위와 확인 항목

  • 깨진 Soft Reference와 누락된 필수 설정
  • 공격 예고·방어 시간과 타격 시간의 관계
  • 중복 슬롯 및 프로젝트 에셋 명명 규칙
검증 Commandlet ↗검사 규칙 ↗
