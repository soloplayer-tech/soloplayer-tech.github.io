CASE 01

월드 목록과 실제 게임 상태 분리

문제·요구사항
여러 월드를 관리하려면 목록에 필요한 정보와 실제 플레이 데이터를 각각 저장하고 선택한 월드를 유지해야 합니다.
구현과 판단
SB_WorldIndex에 월드명·최근 플레이·레벨 등 메타데이터를 저장하고, GUID로 만든 SlotId에 개별 월드 데이터를 보관합니다. 현재 SlotId는 GameInstanceSubsystem에서 유지합니다.
  1. 월드명 입력
  2. GUID SlotId
  3. Index 목록
  4. 선택한 월드 진입

구현 범위와 확인 항목

  • GUID 기반 슬롯 식별자와 중복 월드명 보정
  • 월드 생성·목록·선택·삭제 흐름
  • 목록 메타데이터와 개별 저장 파일 분리
핵심 코드 펼쳐 보기 ＋
NewMeta.SlotId = FGuid::NewGuid().ToString(EGuidFormats::Digits);
NewMeta.WorldName = MakeUniqueWorldName(Index->Worlds, InWorldName);
Index->Worlds.Add(NewMeta);
SaveIndex(Index);
월드 저장 매니저 ↗월드 생성·삭제 담당 커밋 ↗

CASE 02

복원 가능한 ID와 값으로 저장

문제·요구사항
런타임 객체를 그대로 유지할 수 없는 저장·불러오기에서는 다른 시스템의 상태를 다시 구성할 수 있는 데이터가 필요합니다.
구현과 판단
아이템 ID·수량·슬롯, 건축물 ID·Transform, 드랍 아이템 ID·수량·Transform을 SaveGame에 기록합니다. GAS 능력치는 Max 값을 Current 값보다 먼저 적용해 복원 순서를 명확히 했습니다.

구현 범위와 확인 항목

  • 플레이어 위치·능력치·인벤토리·핫바 연동
  • 배치 건축물과 SavedWorldDrop 태그가 있는 드랍 수집
  • 레벨 고정 픽업과 플레이어 드랍의 수명 정책 구분
핵심 코드 펼쳐 보기 ＋
ASC->SetNumericAttributeBase(
    UPlayerAttributeSet::GetMaxHealthAttribute(), Save->SavedMaxHealth);
ASC->SetNumericAttributeBase(
    UPlayerAttributeSet::GetHealthAttribute(), Save->SavedHealth);
저장 데이터 구조 ↗저장·복원 담당 커밋 ↗드랍 아이템 수명 ↗

CASE 03

설정 화면의 임시값과 실제 적용값 분리

문제·요구사항
키 선택 즉시 입력을 바꾸면 취소가 어렵고, 다른 동작에 이미 할당된 키와 충돌할 수 있습니다.
구현과 판단
PendingBindings와 창을 열 때의 적용값을 따로 보관합니다. 임시 변경값과 Input Mapping Context를 검사해 중복 키를 찾고 Apply·Revert·기본값 복원 흐름을 구성했습니다.
  1. 키 선택
  2. Pending 값
  3. 중복 검사
  4. 적용 또는 되돌리기

구현 범위와 확인 항목

  • Enhanced Input 사용자 키 설정과 비동기 저장
  • Master·BGM·SFX 및 그래픽·프레임 옵션 연동
  • 맵 전환 시 MoviePlayer 기반 로딩 화면
키 설정·충돌 검사 ↗중복 키 방지 담당 커밋 ↗로딩 화면 ↗
